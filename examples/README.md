# Examples

Everything in this directory is **synthetic**. It is generated by
[`caddiff/make_moved_fixture.py`](../caddiff/make_moved_fixture.py) from primitives
(boxes) — there is no customer CAD data anywhere in this repository, and there never
should be.

```
fixtures/
  moved_old.stp        three parts: BASEPLATE, SLIDER, BRACKET
  moved_new.stp        same assembly with two deliberate changes
expected/
  report.html          what `caddiff diff` produces on that pair
  report.md            the same report as Markdown
  images/*.png         overview + old/new close-ups for each change
  summary.json         the expected values, in machine-readable form
```

## What the pair contains

| Part | Change |
|---|---|
| `BASEPLATE` | none — the control case, it must **not** appear in the output |
| `SLIDER` | translated 5 mm → `moved` |
| `BRACKET` | a 4×12×4 mm block cut away → `shape_changed`, 192 mm³ removed |

So the expected result is exactly **2 geometric differences** and exit code **1**:

```console
$ caddiff diff fixtures/moved_old.stp fixtures/moved_new.stp -o out
$ echo $?
1
$ python -c "import json;print(json.load(open('out/diff_manifest.json'))['summary']['geometry_diff_count'])"
2
```

## Regenerating

Rendering is the slow part (≈75 s on a 3-part assembly, no GPU), so these files are
committed rather than generated in CI on every run.

```console
$ export FREECAD_PYTHON=/path/to/FreeCAD/bin/python.exe   # Windows: the FreeCAD distribution ships its own python
$ # Linux instead: export FREECAD_PYTHON=/usr/bin/python3 PYTHONPATH=/usr/lib/freecad/lib   (see ../docs/pipeline.md)
$ python caddiff/make_moved_fixture.py examples/fixtures
$ caddiff diff examples/fixtures/moved_old.stp examples/fixtures/moved_new.stp -o out
```

Then copy `out/report.html`, `out/report.md` and `out/images/` over `expected/`.

`summary.json` is what CI asserts against — it deliberately contains **no absolute
paths**, so it is portable across machines:

```json
{
  "exit_code": 1,
  "geometry_diff_count": 2,
  "by_change_type": { "moved": 1, "shape_changed": 1 }
}
```

## Two things the example deliberately exercises

**1. Both versions are exported from a document with the same name.** This is not
cosmetic: STEP export writes the document name into the top-level `PRODUCT` record, and the
BOM layer compares parts by `PRODUCT` name. Naming the two documents differently
(`MovedOld` / `MovedNew`) makes the tool report one added part and one removed part — a
difference that does not exist in the geometry. That is a real limitation worth knowing:
**the top-level assembly product participates in BOM comparison**, so renaming an assembly
between revisions shows up as an add + remove.

**2. The assembly container is reported as skipped, not as a difference.** STEP import
builds the top-level assembly as an `App::Part` container, and that container arrives as a
BOM candidate. Its "shape" is the union of its children, so *any* child change would make
it report a difference too — turning "2 things changed" into "3 things changed". `caddiff`
therefore skips containers whose children are themselves candidates, and records them
honestly:

```json
"skipped_parts": [ { "name": "MovedFixture", "reason": "assembly_container" } ]
```

A container with no compared children is still treated as an ordinary part, so a real part
can never be silently dropped this way.
